**`repro ci` runs the checks as one line of a GitHub Actions workflow each, and `repro ci init` writes the workflows.** `repro ci claims` runs what `repro verify` runs and then, where the manifest declares a command, what `repro stale` reports; `repro ci reruns` runs what `repro reproduce` runs, on the machine the job runs on, and appends the re-run to `.repro/reproductions.jsonl` as that command does. Each prints what those commands print, takes `--policy`, and appends a Markdown summary to the file `GITHUB_STEP_SUMMARY` names, or `--summary PATH`, which GitHub shows on the page of the run. Every count in a summary carries its denominator, `75 of 76 assertions verified, 1 mismatch`, `12 of 12 declared files match their pins`, `57 current of 57 assertions that read a file with a recorded producer; 19 read files no command is recorded for`, and an assertion that is `unchecked` or `not found` is counted under that word. Warnings are counted beside the outcomes and change none. The claims summary also carries what `repro numbers` counts in the manuscript's text, `458 numbers in 1 text: 38 bound, 80 set aside by rule, 0 set aside with a reason, 340 unbound`, which grades nothing. An assertion that is not verified is listed with its claim id, the value the manuscript prints, the value the file holds and the address; each list stops at 20 lines and says how many more there are. A summary ends on what the check does not show. `repro ci claims` exits 1 where the policy fails the verification or the staleness report and 2 with no manifest; a manifest that declares no command is said to in one line and does not change the code. `repro ci reruns` exits as `repro reproduce` does, 2 with no command declared. `repro ci init` writes `.github/workflows/claims.yml`, and `reruns.yml` with `--reruns`: the package pinned to the installed version, each action pinned by commit, `contents: read`, on a push to the default branch and on every pull request. Each workflow is named for its check, `claims` and `reruns`, because GitHub's badge is per workflow and prints that name beside `passing`; `--name CHECK=TEXT` renames one and `--prefix` changes the file names. It prints one badge line per workflow, with the owner and repository read from the `origin` remote, and `--readme` puts them on one line under the first heading of `README.md`, once. A workflow it wrote is replaced only with `--force`, a file of that name it did not write is never replaced, and outside a git repository or with no `repro.yaml` it exits 2 and writes nothing. `repro verify`, `repro stale` and `repro reproduce` report as before.
