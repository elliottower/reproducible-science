**`repro ci` runs each check as one line of a GitHub Actions workflow, and `repro ci init` writes the workflows.** `repro ci prereg` runs `prereg check`, `repro ci results` runs `results verify --files`, `repro ci citations` runs `citations verify --claims <dir>`, each found and pointed as `repro check` finds and points it; `repro ci claims` runs what `repro verify` runs and then, where the manifest declares a command, what `repro stale` reports; `repro ci reruns` runs what `repro reproduce` runs, on the machine the job runs on. Each prints what those commands print and appends a Markdown summary to the file `GITHUB_STEP_SUMMARY` names, or `--summary PATH`, which GitHub shows on the page of the run. Every count in a summary carries its denominator: `75 of 76 assertions verified, 1 mismatch`, `1 of 1 frozen plan unchanged since the freeze`, `1 of 2 recorded files match the hash recorded, 1 changed`, `1 found, 0 not found, 1 unchecked of 2 quotations`. An assertion or quotation that is `unchecked` or `not found` is counted under that word, warnings are counted beside the outcomes and change none, the claims summary carries what `repro numbers` counts in the manuscript's text, which grades nothing, a plan never frozen is counted apart and called a draft, each list stops at 20 lines and says how many more there are, and each summary ends on what its check does not show. The counts of the three tools are read from the JSON each now writes with `--json`. `prereg`, `results` and `citations` exit 0 where the check passed, 1 where it failed, and 2 where it could not be made or there is nothing to read, as `repro audit` reads the same command, with one difference: a citations run in which some quotations were found, none was not found and the rest were unchecked passes, and its summary opens on how many were not checked. A run that read no source exits 2. `repro ci citations --fetch-sources` runs `citations fetch` first, takes no exit code from it, and counts what was fetched. `repro ci claims` and `repro ci reruns` take `--policy` and exit as `repro verify` and `repro reproduce` do; a manifest that declares no command does not fail `claims`. `repro ci init` writes a workflow under `.github/workflows/` for each of prereg, results, claims and citations the repository keeps a record for, says which it skipped and why, and writes `reruns.yml` with `--reruns`: `reproducible-science` pinned to the installed version, each action pinned by commit, `contents: read`, on a push to the default branch and on every pull request. Each workflow is named for its check, because GitHub's badge is per workflow and prints that name beside `passing`; `--name CHECK=TEXT` renames one and `--prefix` changes the file names. It prints one badge line per workflow written, with the owner and repository read from the `origin` remote, and `--readme` puts them on one line under the first heading of `README.md`, once. A workflow it wrote is replaced only with `--force`, a file of that name it did not write is never replaced, and outside a git repository or with no record to check it exits 2 and writes nothing. `repro verify`, `repro stale`, `repro reproduce` and `repro check` report as before. `repro ci reruns` runs nothing by default: it reads the record of re-runs as `repro stale` does and passes where every declared command has a recorded re-run that reproduced, made over the command and inputs as they are now, failing a command that is stale, never rerun or undetermined under any policy; `--run` runs the commands in the job as `repro reproduce` does. With that, `repro ci claims` takes its verdict from the verification alone and reports freshness without grading it. The reruns workflow is named `reproduced`, and `repro ci init` writes it only where the manifest declares a command and the record holds a re-run; `--run-reruns` writes the one that runs the commands. Every summary opens on what its check compares and a link to its section of the documentation. `repro ci init` prints two badge lines per workflow, GitHub's own and one drawn by shields.io with the check's icon on a dark label, which works only for a public repository, and `--readme --branded` puts the second in the README.
