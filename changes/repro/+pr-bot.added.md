**`repro bot init` writes a pull-request bot as three workflows in the author's own repository.** `repro-bot-check.yml` runs on `pull_request` with `contents: read`, checks out the head commit, and uploads what `repro bot check` found: each assertion that is `mismatch`, `not-found` or `error`, as `repro export` records it, or whose producing command is `stale`. `repro-bot-post.yml` runs on `workflow_run`, checks out nothing, refuses findings unless the pull request they name is at the commit checked, and comments once per assertion, on the manuscript's line where it is in the diff and in the conversation otherwise. Each comment carries a hidden marker with the claim, the assertion, its SARIF fingerprint and a digest of what was found; a later run edits it, marks it fixed when the assertion passes, and never posts it twice. `repro-bot-reply.yml` runs on `issue_comment` and `pull_request_review_comment`, checks out nothing, and records a reply that starts with 1 to 4 from someone with write access: 1 and 2 are noted in the comment and change no file, 3 and 4 commit a `set_aside` entry with the reason, the login and the time to the pull request's branch, editing `repro.yaml` as text so no other byte changes. On a pull request from a fork the bot comments and commits nothing. Actions are pinned by commit, and `init` never replaces a workflow it did not write.
