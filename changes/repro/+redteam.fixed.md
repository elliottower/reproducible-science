**`repro verify` finds the preregistrations `prereg check` finds.** It looked for `PREREG.md` three levels down at most and never for a registration frozen by a commit line, so a nested plan or a commit-pinned registration that `prereg check` reported changed was "not used here" and the run exited 0. It now asks `prereg` which registrations a project holds, and a note `prereg check` raises without failing, such as a freeze held to an access floor lowered after the fact, is shown under its pass.

**`repro verify` names each output `results` passed as `RESEALED`, and takes `--max-unbound`.** A passing results section printed one line, so an output recorded under more than one hash was invisible in the project report. The notes on `reported` values appear in the claims section, and the unbound-number warning `claims verify` now gives appears there too unless the project keeps a ledger, where the coverage section reports unbound numbers once and `--max-unbound` applies to it; and the bundled `results` skill lists the `RERECORDED` state.

**Red-team fixes in `repro reproduce`, `repro mcp` and `repro verify`.** `repro reproduce` no longer reports a reproduction for a command that copies the pinned output: a command naming a path inside the project by absolute path, or the output's own path, fails with `command_names_the_project` before it runs, and the pinned output is moved out of the project, under a name made at random and noted in `.repro/set-aside.json`, while each command runs; an interrupted run's output is put back by the next. A record `--isolate` leaves unchecked is said as such on the summary line. `--isolate` runs commands under `sandbox-exec` or `bwrap` with the project unreadable. A witness copied from `GITHUB_*` variables is said as `unverified`, and `.repro/reproductions.jsonl` is a hash chain with a head file, `.repro/reproductions.head`, which `repro reproduce` refuses to append to when broken and `repro stale` and `repro verify` report. `mark_reviewed` in `repro mcp` records its review as agent-recorded. `repro verify` runs `citations coverage` and `results coverage` over the manuscript, a warning by default and a failure under `strict`, and where every check passes says how many findings `strict` would fail (`--explain` lists them). Under `--policy strict`, `results verify` and `citations verify` run with their own `--strict`, so the count `strict` gives on a default run is what that run fails. Coverage reads a Markdown manuscript as Markdown and never reads a preregistration as the manuscript, and the count `strict` gives counts a quotation once whatever number of warnings it carries.
