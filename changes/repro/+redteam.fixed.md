**`repro verify` finds the preregistrations `prereg check` finds.** It looked for `PREREG.md` three levels down at most and never for a registration frozen by a commit line, so a nested plan or a commit-pinned registration that `prereg check` reported changed was "not used here" and the run exited 0. It now asks `prereg` which registrations a project holds, and a note `prereg check` raises without failing, such as a freeze held to an access floor lowered after the fact, is shown under its pass.

**`repro verify` names each output `results` passed as `RESEALED`, and takes `--max-unbound`.** A passing results section printed one line, so an output recorded under more than one hash was invisible in the project report. The notes on `reported` values appear in the claims section, and the unbound-number warning `claims verify` now gives appears there too unless the project keeps a ledger, where the coverage section reports unbound numbers once and `--max-unbound` applies to it; and the bundled `results` skill lists the `RERECORDED` state.

**Red-team fixes in `repro reproduce`, `repro mcp` and `repro verify`.** `repro reproduce` no longer reports a reproduction for a command that copies the pinned output: a command naming a path inside the project by absolute path, or the output's own path, fails with `command_names_the_project` before it runs, and the pinned output is moved to the project's directory in the user's cache while each command runs, which stops accidental or naive copying; `--isolate` is the guard against a command that means to copy. An interrupted run's output is put back by the next, and a set-aside note found in the project is warned of and never acted on. A record `--isolate` leaves unchecked is said as such on the summary line. `--isolate` runs commands under `sandbox-exec` or `bwrap` with the project unreadable. A witness copied from `GITHUB_*` variables is said as `unverified`, and `.repro/reproductions.jsonl` is a hash chain with a head file, `.repro/reproductions.head`, which `repro reproduce` refuses to append to when broken and `repro stale` and `repro verify` report. `mark_reviewed` in `repro mcp` records its review as agent-recorded. `repro verify` runs `citations coverage` and `results coverage` over the manuscript, a warning by default and a failure under `strict`, and where every check passes says how many findings `strict` would fail (`--explain` lists them). Under `--policy strict`, `results verify` and `citations verify` run with their own `--strict`, so the count `strict` gives on a default run is what that run fails. Coverage reads a Markdown manuscript as Markdown and never reads a preregistration as the manuscript, and the count `strict` gives counts a quotation once whatever number of warnings it carries. The results line of `repro verify` counts claims marked derived, and `--explain` lists them. Two `repro reproduce` runs on one project no longer overlap: the second waits briefly and then fails with `project_busy`, so CI does not read it as a pass, and a cache entry it cannot use is refused the same way, never with a traceback. An output declared outside the project is never set aside, with a warning; a held file reached through a link, or with more than one name, is never moved; and a relative `REPRO_HELD_DIR` or `XDG_CACHE_HOME` is ignored with a warning.
