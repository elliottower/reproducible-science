**Red-team fixes in `repro reproduce`, `repro mcp` and `repro verify`.** `repro reproduce` no longer reports a reproduction for a command that copies the pinned output: a command naming a path inside the project by absolute path, or the output's own path, fails with `command_names_the_project` before it runs, and the pinned output is set aside while each command runs. `--isolate` runs commands under `sandbox-exec` or `bwrap` with the project unreadable. A witness copied from `GITHUB_*` variables is said as `unverified`, and `.repro/reproductions.jsonl` is a hash chain with a head file, `.repro/reproductions.head`, which `repro reproduce` refuses to append to when broken and `repro stale` and `repro verify` report. `mark_reviewed` in `repro mcp` records its review as agent-recorded. `repro verify` runs `citations coverage` and `results coverage` over the manuscript, a warning by default and a failure under `strict`, and where every check passes says how many findings `strict` would fail (`--explain` lists them).
