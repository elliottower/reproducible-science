**`repro export record` writes one record per checked assertion, as JSON Lines.** Each line states what was observed and no verdict: the checker and its version, the manifest and its digest, the claim and where the manifest declares it, each file read with its pinned digest, its digest on disk and its `validity`, the address as a tagged object, the value stored there, the value the manuscript prints (`printed`), the comparison mode and tolerance, and the outcome. An assertion is identified by its claim's id, its kind, its name and its `position` among the claim's assertions of that kind and name. `check_type` names the proposition that was checked (`value-comparison`, `passage-presence` or `correspondence`), since two tools can use one word for different checks. `outcome` is one of `match`, `mismatch`, `not-found`, `not-checked` and `error`, each defined by its preconditions in SPEC 7.7, and `native_outcome` and `native_reason` carry the words `repro verify` prints. Where a declared command writes a file the assertion reads, an `execution` block adds the state `repro stale` gives and each command upstream with its latest recorded re-run. `repro.record.validate` refuses a record no check could have produced, such as a `mismatch` without both values or a stored value on a check that did not run, and a word, check type or address kind a reader does not know is kept and never read as a `match`. The assertions are evaluated by the functions `repro verify` uses. The command executes nothing, writes only the output it is asked for (`-o FILE`, or standard output) and exits 0 whatever the outcomes. Experimental: the format is `repro.check/0.1-experimental`, each record names it, and the JSON Schema generated from the model is `docs/schemas/repro.check-0.1-experimental.schema.json`. `repro verify` prints and exits as before.
