**An edit through a symlink to a frozen plan is refused.** `frozen_file_before_edit.py`, shipped in both the `prereg` plugin and the bundle, compared the path an edit named against `PREREG.md` and `.prereg/<name>.json` by name, so `link.md` pointing at a frozen plan was edited through, and so was `prereg.md` on a case-insensitive disk. It now checks the path as named and with its symlinks resolved, and where the file exists compares it with `os.path.samefile` against `PREREG.md` and every file with a freeze record beside it. The reasons it gives are unchanged. The `repro` mod's guard does the same with `$.fs.stat(path, { resolve: true })`, reading the last name back from its folder's listing so a case alias is matched to the file the disk stores. Where the hook cannot load its detector from `frozen_plan_changed.py`, it refuses an edit to any file that could be frozen, a `PREREG.md` in any case or a file beside `.prereg/`, instead of allowing every edit in silence. A hard link to a frozen plan is still not matched by the mod, whose file interface reports no device or inode.
