**A `prose` locator reads a number printed against the text that follows it.** The value was the whole run of non-whitespace characters after `before`, and `after` had to begin past it, so a cell of a printed table, `| 3| 0.459| 0.124|`, was read as `0.459|` and reported `value_not_numeric` whatever `after` said, and `93.1%` and a number closing a sentence could not be bound either. The value is now the whole run where `after` begins past it, and otherwise the run cut at the first place inside it where `after` begins, so `before: "| 3|", after: "|"` reads `0.459` and `after: "."` reads `3.14.` as `3.14`. With `after` omitted the run is still read whole. An anchor never splits a number: `after` may not begin, and `before` may not end, inside digits joined by a decimal point, a grouping comma or underscore, or an exponent, so `after: "9"` on `0.459` reads nothing where a cut would read `0.45`. A `before` ending inside a number, `before: "0.4"`, read the rest of it, `59`, and is now `passage_absent` with the number named in the detail. Four conformance fixtures cover a printed table, and declare the three stages as well as the outcome.
