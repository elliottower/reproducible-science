**`repro export sarif` writes a SARIF 2.1.0 log from the check records, for GitHub code scanning.** A `mismatch` is a result at `kind: fail`, `level: error`, a `not-found` one at `level: warning`, and an `error` a result and a notification that marks the run as failed. An assertion that was `not-checked` is never a result, since it is neither a finding nor a pass: it is a notification at `level: warning` on the invocation, counted by reason in the run's properties. A `match` is written only with `--include-matches`, as `kind: pass`. Each result is shown at one line: that of the sentence, where the claim quotes one from a text file that holds the passage exactly once, and otherwise the assertion's line in `repro.yaml`; the files it reads are related locations and a line is never estimated. `partialFingerprints` carries a digest over the claim's id, the assertion's kind, name and position and the address or passage it declares, also as `primaryLocationLineHash`, the only one GitHub reads, so an alert follows its assertion when a sentence moves. The log is a lossy projection: the whole record is in each result's property bag under `repro/checkRecord`, and the README lists the fields SARIF carries nowhere else. A log of more than 5,000 results, which GitHub truncates, is written whole with a warning. The command executes nothing and exits 0 whatever the outcomes. `repro verify --format sarif` is unchanged.
