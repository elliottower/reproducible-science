**`repro verify` keeps a record of what each assertion said when it was checked, and `repro why` shows it.** After a check does not verify, the `reported` value, the address or the claim's text can be edited until it does, and the report of the last run shows none of that. Each `repro verify` now appends to `.repro/checks.jsonl`, beside the record of re-runs, one entry for every assertion whose `reported` value or passage, address, claim text, artifact digest or outcome differs from the last check recorded for it: what it declared, the digest of each file read, the outcome and when. A run that finds nothing changed writes nothing, an earlier line is never rewritten, and what the command prints and the code it exits with are unchanged. `--no-record` leaves the file alone, and the `repro-verify` and `repro-verify-strict` hooks and `repro audit` pass it, so a commit and an audit still write nothing. Under `established`, `repro why <claim-id>` ends an assertion's lines with the states recorded for it where there is more than one, `checked 2026-10-13T21:03:07+00:00: reported 0.92 at /acc, results 6eaca0ac7275: mismatch` and then `since 2026-10-13T21:03:22+00:00: reported 0.91 at /acc, results 6eaca0ac7275: verified (after mismatch: reported changed)`, and shows an assertion edited since the last recorded check as `now`. `--format json` carries the states as `history` and `now` on each assertion. An assertion is followed by its claim's id, its kind, its name and its position among the claim's assertions of that kind and name, so a claim given another id starts a new history.
