**`repro verify --record` keeps a record of what each assertion said when it was checked, and `repro why` shows it.** After a check does not verify, the `reported` value, the address or the claim's text can be edited until it does, and the report of the last run shows none of that. `repro verify` writes nothing, as before. With `--record` it appends to `.repro/checks.jsonl`, beside the record of re-runs, one entry for every assertion whose `reported` value or passage, address, claim text, artifact digest or outcome differs from the last check recorded for it: what it declared, the digest of each file read, the outcome and when. A run that finds nothing changed adds nothing and an earlier line is never rewritten. Ask for it before and after editing a claim, or in the project's own CI job that commits the record. What the command prints and the code it exits with are the same with the flag as without; where the record cannot be written, one line on standard error says so and why, `record not written: .repro: File exists`, and the exit code is still the verification's. Under `established`, `repro why <claim-id>` ends an assertion's lines with the states recorded for it where there is more than one, `checked 2026-10-13T21:03:07+00:00: reported 0.92 at /acc, results 6eaca0ac7275: mismatch` and then `since 2026-10-13T21:03:22+00:00: reported 0.91 at /acc, results 6eaca0ac7275: verified (after mismatch: reported changed)`, and shows an assertion edited since the last recorded check as `now`. With no record it prints nothing more. `--format json` carries the states as `history` and `now` on each assertion. An assertion is followed by its claim's id, its kind, its name and its position among the claim's assertions of that kind and name, so a claim given another id starts a new history.
