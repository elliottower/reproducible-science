**`repro venue acm` drafts an Artifact Appendix from what the repository records.** The fields are those of the Unified Artifact Appendix template ACM conferences use for artifact evaluation, copied into the package with the commit of the template they were read at. A field a record bears on carries one line per fact, each naming its record: the commands under `regenerations`, the duration and environment of the last re-run in `.repro/reproductions.jsonl`, the claims in `repro.yaml` and the ledger, the plans frozen with `prereg`, the DOI and license in `CITATION.cff`, `LICENSE`, the lockfiles at the top of the project and the `origin` remote. Each such field is marked DRAFT with the records it came from; every other field is marked TODO and left for the authors. A yes or no is filled in only where a record settles it with no judgment involved, and is marked DRAFT with that record named: a DOI in `CITATION.cff` or `codemeta.json`, or a Software Heritage ID in either or in the README, answers Yes to "Archived (provide DOI)?", while a GitHub or GitLab address alone does not; any of those, or `repository-code` in `CITATION.cff`, `codeRepository` in `codemeta.json` or an origin repository in the manifest, answers Yes to "Publicly available?" with "author: confirm this repository is public"; and a declared command answers Yes to "Workflow automation framework used?". Plans are found as `prereg check` finds them, leaving out those under folders of tests, fixtures and examples, or named with `--plan`. Output is Markdown, LaTeX in the template's layout, or JSON, and `--output` never replaces a file without `--force`.
