**A freeze made over is caught in history, not only on disk.** Editing a frozen plan together with the digest in its freeze record, or deleting the record, editing the plan and freezing again, left a file and record that agreed, and `prereg check` passed. It now reads the plan at the commit the record names, which must hold the bytes the record froze, and reads the record's own history: a record rewritten, or deleted and written again with other content, is `REWRITTEN` and exits 1, and a committed record that is gone is `RECORD GONE`. A commit the repository does not hold, a file the commit does not contain and a freeze forced over uncommitted bytes (now recorded as `uncommitted`) are noted and do not fail. On a registration frozen by a commit line, a line that named another commit in any committed version is `CHANGED`, and lines added after the frozen text count as `appended` only where they are log entries that start with their date; a new criteria section is `CHANGED`. `prereg freeze --companion PATH` freezes a file the plan relies on, such as `analysis_plan.yaml`, and `check` and `check --staged` fail on any change to it. A freeze records where it sits in the results ledger, and the runs `results label` declared after the fact, which `check`, `check --json` and `repro verify` show.

**A timestamp proof deleted after it was committed is reported as deleted.** `prereg check` said `timestamp owed` for a frozen file whose committed `.ots` proof had been removed, the same words it uses where the calendars could not be reached, so the loss of the outside date read as one that never existed. It now names the commit that added the proof and how to restore it. The exit code is unchanged.
