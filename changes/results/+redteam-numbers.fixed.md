**A claim's numbers are read against the outputs of the run it names, and a rewritten ledger is caught by its own history.** `results claim` warned of nothing when the sentence printed 0.9913 and the run wrote 0.4213; it now reads the run's outputs as text and warns where a number the claim prints is held by none of them at the printed precision, and `--strict` refuses the claim. `results verify` lists those claims and claims whose run's every output was retired, and `--strict` fails them. An output recorded again under other bytes with nothing sealed between the two runs is refused by `results run` and fails `verify --files` as `RERECORDED`; a re-run that seals its inputs first is recorded as before. `verify` fails where a commit holds a version of the ledger or its anchor that the ledger on disk does not extend, `reanchor` refuses in the same case, a deleted timestamp proof is reported, and every `.results/` ledger below the project is verified with it. A sealed tree says which symlinks and cache files its digest skipped. `results coverage` binds a printed number only where a claim prints it with the words around it or the claim's run wrote it, so a claim listing numbers no longer covers a manuscript; it reads values set by simple `\newcommand` and `\def` macros, decimals written `.049`, the Unicode minus and thin-space grouping, and exempts `0.95`, `100` and the other constants only where a formula prints them.
