**`results claim --frozen-at` names a freeze record, and the record dates the freeze.** Any reference git resolved was accepted, `HEAD` included, and the freeze was dated by its commit date, so a plan frozen after the outcomes were seen, in a commit backdated with `GIT_COMMITTER_DATE`, made a confirmatory claim pass. `--frozen-at` now takes the full commit id a `prereg freeze` record names, and the freeze is placed by the record's position in the ledger, or by its `frozen_at` where it holds none, never by a commit date. `results verify` does the same for claims already in the ledger, and lists a claim citing a commit no record names apart from the protected ones. A confirmatory claim whose run was recorded before the plan was frozen is flagged at the claim and by `verify`, and is not refused.

**A claim's numbers are read against the outputs of the run it names, and a rewritten ledger is caught by its own history.** `results claim` warned of nothing when the sentence printed 0.9913 and the run wrote 0.4213; it now reads the run's outputs as text and warns where a number the claim prints is held by none of them at the printed precision, comparing a stored fraction with a printed percentage only where `%` or `percent` marks it, and `--strict` refuses the claim. `--derived "how"` records that a claim's numbers are derived from the outputs and exempts them from the comparison. Zero-width, format and other blank characters are removed before numbers are read, with a warning, and an output holding a number with a huge exponent no longer crashes the check. `results verify` counts those claims on one line (`--explain` lists them), lists claims whose run's every output was retired, and `--strict` fails them. An output recorded again under other bytes with no input of the earlier run sealed between the two is warned by `results run` (refused with `--strict`) and reported by `verify --files` as `RERECORDED`, which `--strict` fails; the path is still compared, so a file that also changed since is `CHANGED`. Sealing an unrelated file, or sealing an input again with the bytes it had, does not count as a re-run. `results claim` refuses a ledger git history shows was rewritten. `verify` fails where a commit holds a version of the ledger or its anchor that the ledger on disk does not extend, `reanchor` refuses in the same case, a deleted timestamp proof is reported, and every `.results/` ledger below the project is verified with it. A sealed tree says which symlinks and cache files its digest skipped. `results coverage` binds a printed number only where a claim prints it with the words around it or the claim's run wrote it, so a claim listing numbers no longer covers a manuscript; it reads values set by simple `\newcommand` and `\def` macros, decimals written `.049`, the Unicode minus and thin-space grouping, and exempts `0.95`, `100` and the other constants only where a formula prints them.

**A freeze record places a freeze only where its plan stands behind it.** A record is placed only where its plan exists and the commit it names holds the plan with the digest it records, so a record with no plan, or edited after the fact, places nothing. `prereg freeze` writes a `freeze` event into the results ledger, and that event, inside the hash chain, places the freeze; otherwise the position the record states must not be earlier than the ledger as committed at its commit, and where a ledger exists the record's own time places nothing. A record stating a ledger position places the freeze only where the chain holds its freeze event at that position. A freeze made before any ledger existed precedes every ledger event where the newest commit that touched its record is a strict ancestor of the first commit that added the ledger, by commit order and never by date; uncommitted, it places nothing.
