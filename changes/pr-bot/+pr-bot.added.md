**`reproducible-science-pr-bot`, a pull-request bot published as its own distribution.** On a pull request it comments once for each claim in `repro.yaml` that fails or went stale, as `repro export` records it, and records a reply that starts with 1 to 4 from someone with write access: 1 and 2 are noted in the comment and change no file, 3 and 4 commit a `set_aside` entry with the reason, the login and the time to the pull request's branch, editing the manifest as text so no other byte changes. `check` runs where the pull request's files are, with a read-only token; `post` and `reply` run with a token that writes, check out nothing, and refuse findings that do not belong to the pull request, commit and branch the run checked, or that name another file than the manifest. Each comment carries a hidden marker; a later run edits it, marks it fixed and resolves its thread when the assertion passes, and never posts it twice. On a pull request from a fork it comments and commits nothing. After a commit it starts the checks again with `workflow_dispatch`, so a required check runs on the new head.
