**`citations audit` compares the venue by identifier.** The record's venue is the identifiers its registries give it: Crossref's ISSNs for a journal article, PubMed's NLM id and ISSNs, a DataCite container's ISSN, the ISSNs Semantic Scholar or OpenAlex give a work found by title, or the OpenAlex work's primary source, widened through Wikidata to the items that hold them. The entry's `journal` or `booktitle`, or its `series` where it names neither, is resolved to the same kinds of identifier through Wikidata's labels, aliases, short names and ISO 4 abbreviations and OpenAlex's source names; an `issn` field is used as given. A shared identifier is a match. A mismatch needs the entry's venue resolved to exactly one registry venue, identifiers the record carries itself, and an ISSN, NLM id or DBLP key on both sides with none shared; it is reported like a wrong year and fails `--strict`. Anything else is not comparable and is listed with both names, so a person can compare them. No string rule decides a venue: normalization only picks a registry's candidates. Lookups are cached, paced, unkeyed and sent no contact address. The Semantic Scholar title search now asks for `publicationVenue` and `journal`, so a cached search from an earlier version is asked again once. API keys are optional and add venues where a lookup was refused: `SEMANTIC_SCHOLAR_API_KEY` is sent on every Semantic Scholar request, and `OPENALEX_API_KEY` only on the retry of a request OpenAlex refused unkeyed, as a bearer header. Neither key is ever part of a URL, so neither reaches a cache file, a report or an error message.
