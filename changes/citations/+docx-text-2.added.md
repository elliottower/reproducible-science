**`docx-text` version 2 reads a `.docx` from its own XML, in document order and with its notes, headers and text boxes.** It reads the body in document order, with each table where it stands, a table nested in a cell after its row, text boxes, content controls (a reference manager's citations among them), hyperlink text, symbols as the characters they draw, a ruby's base text and the result of a field; then each footnote and endnote, numbered 1, 2, 3 in the order the text refers to them; then each header and footer once. Tracked changes are read as accepted, in equations too. Comments, automatic list numbers and the result of a page-number field (`PAGE`, `NUMPAGES`, `SECTIONPAGES`, `PAGEREF`) are not read. It needs no library: `python-docx` is now needed only for version 1. A part declaring a document type and a file whose XML inflates past 128 MiB are refused as unreadable. A source recording `extractor_version: 1`, and one that records no version but already holds quotations or a `derived_sha256`, is read by version 1, so its pins still hold; a source with nothing pinned yet is read by version 2, and `citations pin` now records the extractor and version that read a source its suffix chose a built-in extractor for. A claims file naming a version no build ships is told every version this one does.
