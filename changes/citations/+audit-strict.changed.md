**`citations audit --strict` fails on an entry not found, unless its key is on a list of entries checked by hand.** A not found is a book, a report or a thesis, or a reference to a work that does not exist, and the report cannot tell them apart, so `--strict` now exits 1 on one until a person has looked. An entry whose own DOI or PMID every registry answers 404 for is reported as `not found` too, with `not_found_by: identifier`. A thesis, a chapter, a report or a dataset an author has checked goes in a plain file beside the bibliography, `references.checked.txt` for `references.bib` or `checked.txt` in a library, or the file `--checked PATH` names: one key per line, `#` for a note. A listed key is still reported as `not found (marked as checked)` and does not fail the run; a listed key that is found and disagrees fails as any other, a listed key that is found at all is printed as a warning, a listed key whose own DOI or PMID resolves nowhere is excused but warned about as possibly mistyped (`checked_list.identifier_does_not_resolve`), and a listed key the bibliography does not have is warned about as stale. The file's path and SHA-256, the keys read and the stale ones are in `--json` under `checked_list`, and each entry carries `checked_by_hand`. Without `--strict` every row is reported and the command exits 0, as before.
