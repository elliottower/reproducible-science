**Two artifact ids for one file are a policy finding, and a correspondence over them is not compared with itself.** Two artifacts whose paths resolve to one file now carry `same_path_as` on their `ArtifactState`, and two files at different paths holding the same bytes carry `same_digest_as`, read from the digests computed for the pins. A policy reports each pair once, naming both ids: one file under two ids is `artifact.alias`, a warning under `exploratory` and `publication` and an error under `strict`; the same bytes at two paths is `artifact.same_bytes`, a warning under every profile, since identical outputs can be legitimate. A correspondence whose sides read one place through two such ids is `sides_read_one_place`, as through one id, and its detail says whether the ids are one file or hold the same bytes. Where one side's anchors also match places the other does not read, the pair is still refused, and the detail now says which place is shared, which other places each side matches, and which side or sides to narrow.
