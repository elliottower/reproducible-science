**`claims from-paperdelta` reads a PaperDelta report into one check record per occurrence and per comparative claim.** It reads `report.json` with the `paperdelta.yaml` it was made from, refused unless the report records a sha256 for it and that is its sha256, and writes JSON Lines with `paperdelta` as the checker and its status and error code as its own words. `pass` is `match` and `mismatch` is `mismatch`; `unknown` is placed by its error code, and a code the reader does not list is `not-checked`. A `pass` is `not-checked`, with the diagnostic named, where the report as a whole is unsettled: a finding on the project or on anything else that is no one item, such as `INPUT_CHANGED`, `INCOMPLETE_COVERAGE` or a manuscript file, or an exit code the items' own findings do not account for; an exit code one number's own `unknown` accounts for leaves the others as reported. A report whose metric value is not decimal text is refused. An occurrence of a metric reduced `unique` is a `value-comparison`; one reduced `mean`, `sum` or `count`, or a statistic printed as its mean, is an `aggregate-comparison` with one read per selected row; a derived metric, any other statistic and a comparative claim are `other`, which no exporter passes on as a match. Every file is `unpinned_artifact`, with the digest the report records as on disk. A time written without a UTC offset is refused unless `--offset +HH:MM` gives it. `--rerun` also puts each completed comparison to this toolkit's rule and writes both answers, with a count of the occurrences where the two rules disagree. The check record now knows `paperdelta`'s words, `pass`, `mismatch` and `unknown`.
