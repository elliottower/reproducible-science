**`claims from-corebench CAPSULE TASKS` reads a CORE-Bench capsule and its task into a draft manifest and its open items.** The task file may hold one task or a list, and the capsule is found by its folder's name or `--capsule-id`. Each file under the capsule's `results/` in a format a backend reads becomes an artifact, pinned by sha256, and each question a claim whose text is the question as written. A task states the value and not where a file holds it, so each claim has one open item: the address of a numeric answer, or the passage of a result file that prints any other answer. The task's numbers are read as the decimals it writes, so `0.8130` keeps its trailing zero. A numeric item lists as candidates every address in the pinned JSON, YAML and delimited files at which a check of the task's value would match, and none is written into the draft: an integer answer matches every stored value that rounds to it, and where the task's runs disagree no candidate is listed. Nothing in the capsule is run, and files are read with JSON, the safe YAML loader and the `csv` module only.

**Every question is an open item, and a candidate is never written into the draft.** An item is `unique` where exactly one candidate passes the guards, listed first: the value carries at least three significant digits and is not an integer below 1000, and every label set the address belongs to (a JSON mapping's keys, a table's column names, a column of row names) that the question names a member of is named through the address's own label. Otherwise `reason` says why: no match, a value a match of which may be chance, a label no matching address carries, several passing, or runs that disagree. Files are read guardedly: a link out of the capsule is not followed and not declared, a Git LFS pointer is declared without a pin, a YAML result giving a key twice is not searched, each listed under `not_checked`, and a task file giving a key twice is refused.

**`from-corebench` searches the console log Code Ocean writes, and reads hostile files without hanging or crashing.** `results/output`, and any result file with no suffix that holds text, is pinned as `text/plain` and searched up to 5,000,000 bytes, as are `.txt`, `.log` and `.out` files: each candidate there is a `prose` locator whose anchor is the text before the number, kept only where the prose backend resolves it to that number. A candidate whose address does not carry a split the question names (test, train, validation, with their variants) fails the guards, so "test accuracy" never marks `train_acc` unique. A JSON number out of range or not finite, a YAML alias, nesting past 64 levels and a YAML integer past Python's digit limit each make the file `not_checked` with the reason; a task file with any of them is refused. The YAML refusals hold for `from-codecheck` as well.

**A long log or a hostile cell no longer stalls the search, and no question is dropped.** A number longer than 60 characters or past 100 powers of ten is passed over in a CSV cell or a text file as in JSON. A text file is read and its numbers parsed once per run, each distinct numeral is compared once, and at most 20 places in text are examined for one value; the item says how many more matched (`context.candidates_not_examined`) and is not `unique`. A question only some runs ask is kept, with `context.absent_from_runs`.
