**`claims from-clawbio` reads a ClawBio skill's output folder into a draft manifest and the items it leaves open.** Each file `reproducibility/checksums.sha256` lists becomes an artifact pinned to the digest ClawBio recorded, so a file whose bytes moved since the run verifies as a broken pin; `report.md` is pinned to the bytes read, and it, `commands.sh` and `environment.yml` are pinned in the open items' source. Each number `report.md` prints outside code, read under the rule `claims numbers` uses, becomes a claim whose text is its line, with a quotation of the line marked `basis: inferred` and one open item asking for the address of the value in a pinned table, so a fresh draft is counted as verified nowhere and fails `strict` and `publication` until each value is bound. The addresses in the pinned JSON, YAML and delimited tables at which the printed number would match are listed as candidates in the item and never written into the draft. A label that leaves the folder, a table the checksums do not list, and a number the rule sets aside, a time of day such as `14:22`, or a number in code are passed over with the reason; a table nested deeper than the parser reads is pinned and not searched. `commands.sh` is not declared as a regeneration. `claims.numbers.printed` reads the numbers of a text no manifest binds yet under that rule.
