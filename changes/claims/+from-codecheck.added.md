**`claims from-codecheck` reads a CODECHECK configuration file into a draft manifest and its open items.** It takes a `codecheck.yml` (specification 2.0) by its path, or a certificate's identifier looked up in a copy of the register's `register.json` (`--register`, with `--register-sha256` to refuse any other copy; the sha256 read is recorded), whose configuration file is read from a local copy of its repository (`--bundle`) or, with `--fetch` and for a GitHub repository only, fetched at the commit its default branch points to, which the draft records. It writes `repro.draft.yaml` and `open-items.json` and never overwrites either. Each output file becomes an artifact, pinned by sha256 where it is on disk. Each output in a format a backend reads a value from, and whose comment does not place it outside the paper, becomes a claim whose text is the comment as written, with two open items, the passage of the paper it supports and a value the paper prints from it, because the configuration file states neither. A figure, another format, an output outside the paper, a path outside the bundle and a check that declares no output files are passed over with the reason. The draft carries no certificate field and names nothing by the certificate's identifier, which is recorded only as the source read.

**`from-codecheck` reads guardedly and writes nothing into the bundle.** A configuration file that gives one key twice is refused; an output that is a symbolic link out of the bundle, or a Git LFS pointer, is declared without a pin, gets no claim, and is listed under `not_checked` with the reason; a register folder outside the clone is refused. The configuration file and every file of the bundle are left byte for byte as they were; anything to be written beside another tool's file belongs in a sidecar, `reproducible-science-claim-check.jsonl`.

**Each output not pinned is named with why, and shapes the specification does not give are read or named.** The command lists each output declared without a pin, as `unpinned` in JSON and `not pinned:` in text, saying whether it was not at its path in the bundle or no copy of the bundle was given. A bare string in `manifest` is passed over as not a mapping with `file`; `./t.csv` is the same output as `t.csv`; a `comment` or a `title` given as a list is read as its items joined, and a folded block loses its trailing line break. YAML with an alias or nested past 64 levels is refused.
