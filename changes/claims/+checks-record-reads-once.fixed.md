**`repro verify` and `claims verify` no longer slow down as the record of checks grows by re-reading it.** Each check read the record of checks in the git directory and verified its chain, then verified the whole chain again before appending, and parsed every entry twice and copied every assertion it held. The chain is now verified once, the append reads only the last entry and the head file, each entry is parsed once, and the per-assertion history `repro why` shows is built only where it is asked for. On a 9,860,544-byte record, recording the check of a 100-assertion project took 0.981–1.090 s before and 0.380–0.595 s after. Reading the record is still proportional to its size: each check parses every entry once to find what each assertion said when last checked.
