A complete JupyterLab — file browser, kernel, editable cells — compiled to WebAssembly and
served as static files. Every cell runs the **published package**: `pip install
reproducible-science` gets you the same code.

Nothing is uploaded, and there is no account to create. The first load fetches the runtime,
which takes a few seconds.

You can edit any cell and re-run it, or add your own. The notebook walks through sealing an
input, recording a run, binding a manuscript claim to it, and then breaking each link in turn
to see which kind of failure the tool reports.

## One difference from a terminal

WebAssembly has no process model, so there is no shell. `!results seal x.json` cannot work —
it needs to spawn a process. The notebook uses a small helper instead:

```python
cli("results.cli", "seal", "results.json", "--role", "input")
```

That calls the command's entry point with the argv a shell would have handed it, so the code
path is identical. Only the invocation differs.

## Checking quotations

A [second notebook](/reproducible-science/jlite/lab/index.html?path=citations.ipynb) runs
`citations` over a text source and a PDF: a quotation that resolves, one that does not, a
source edited after it was pinned, and a passage claimed on the wrong page.

The published package reads PDFs by calling `pdftotext`, which is a binary. That notebook
substitutes a pure-Python extractor for that one function; every other part of the package is
the published code.

## Not possible in WebAssembly

`prereg freeze` records the commit a plan was frozen at. Git does not exist in WebAssembly,
so the command cannot run here. Install locally to use it:

```bash
pip install reproducible-science
```
